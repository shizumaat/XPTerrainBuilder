## 1. BLOCKERS — each is one lane; dispatch in parallel

### B1. Sign and notarize the mac app (owner has an Apple Developer account)

Lane `betasign`. Design (RELEASES-PLAN §B4, now concrete):

1. `scripts/sign_app.sh APP IDENTITY [ENTITLEMENTS]` — signs INNER-FIRST:
   every Mach-O the frozen engine carries (`.so`, `.dylib`, the
   `Ortho4XP` executable, `DSFTool`, `Triangle4XP`, `osmium`, `7zz`,
   `nvcompress`, `DDSTool`; discovered with `find` + `file`, never a
   hand list), then the app, each with `--options runtime --timestamp`
   and one entitlements plist. The frozen Python runtime needs
   `com.apple.security.cs.allow-unsigned-executable-memory` and
   `com.apple.security.cs.disable-library-validation` (ctypes-loaded
   GDAL/PROJ dylibs); nothing else until a measured failure asks for it.
   Closing check inside the script: `codesign --verify --deep --strict`
   and `spctl -a -t exec -vv` both pass.
2. `scripts/notarize_app.sh APP` — `ditto` zip, `xcrun notarytool submit
   --wait` with an App Store Connect API key, `xcrun stapler staple`,
   re-zip. Refuses (rc ≠ 0) on any notarytool status other than
   Accepted and prints the log URL.
3. `make_app.sh` keeps auto-detecting an identity; `XPTB_SIGN_IDENTITY`
   set to the Developer ID string makes local builds identical to CI
   (side benefit: a stable cdhash ends the TCC re-prompt after every
   rebuild, memory `tcc-volume-prompt-blocks-engine`).
4. `release.yml` mac job: import the cert into a throwaway keychain,
   sign, notarize, staple, zip. **A tag release with the secrets absent
   FAILS** — no more ad-hoc tag artifacts; `workflow_dispatch` dev builds
   may stay ad-hoc and say so in the artifact name.
5. Release notes: replace the right-click text with "no dialog expected;
   if one appears, the build is not the signed one — report it".

Closing test: the signed, stapled zip downloaded from the workflow
artifact on a clean user account (or after `xattr -w
com.apple.quarantine`), opened by double-click with no Gatekeeper dialog;
it builds one tile end to end and `Ortho4XP --proj-selfcheck` exits 0
under the hardened runtime.

## 5. Sequence

1. Owner: push main; B1 prerequisites (cert, key, secrets); B6 refresh;
   the 1.0.344 sim read.
2. Session: dispatch `betasign`, `betafirstrun`, `betaversion`, `betaci`,
   `betapolish` in parallel (five worktrees; each closes on its own test;
   no five-airport sweep in a lane).
3. Merge in the order B4 → B3 → B1 → B2 → polish (CI must be green before
   the version and signing changes are judged by it).
4. One `workflow_dispatch` Release run on main; download all three
   artifacts; the closing tests of B1–B3 on the downloaded artifacts.
5. App build sweep (orchestrator, once): the five battery airports through
   the harness; the owner's sim read of the beta candidate.
6. Tag `v1.0.<build>-beta.1`; the Release job attaches the artifacts and
   `RELEASE_NOTES-<version>.md`; invite testers.

Wall-clock the sequence costs, from known times: a Release run ≈ 6–8
min; a harness HECA build ≈ 8–10 min; the app build ≈ 15 min; the CI
matrix ≈ 3–5 min per push. The critical path is the owner's B1
prerequisites and the 1.0.344 adjudication, not the lanes.
